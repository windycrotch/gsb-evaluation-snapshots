# 联机断线与并发一致性 · 验证手册

本目录提供两层自动化验证，外加一套可手工复现的双窗口流程。

## 一、协议层测试（无需浏览器，最快）

```bash
node tests/protocol.test.mjs        # 或 npm run test:protocol
```

直连真实 `server.js`，用 `ws` 客户端模拟主机/客机，覆盖：

1. 配对角色与 `input`/`state`/`cmd` 双向中继
2. **同一连接重复 join 幂等**：返回原角色/原房间，不新建房间、不打扰对手
3. **双方几乎同时操作（交叉 cmd）**：两端各恰好收到一条，不会重复
4. 任一方断开 → 存活方收到 `peer-left`，房间立即删除
5. **房间删除后的迟到消息**（input/state/cmd/pick/ready）一律收到 `error/room-closed`，绝不再转发
6. 主动 `leave` 与断连等价，重复 `leave` 幂等
7. 第三个连接不会顶替已配对房间，而是另建新房
8. 断线后重新 join 得到全新房间，命令正常中继（无旧房间状态残留）

## 二、真实浏览器双窗口 E2E

```bash
node tests/e2e.test.mjs              # 或 npm run test:e2e
```

用本机 Chrome（headless=new + SwiftShader）经 CDP 驱动多个真实游戏页面，覆盖：

- **A 配对/开局一致性**：自动配对与自动选人后，两端进入同一对局，
  角色、回合数、比分、对局代号 `gen` 完全一致；主机持续广播快照、客机持续上行，
  客机收到的快照含双斗士完整数据与 `gen`（同时回归了服务端扁平 `state` 消息的中继）
- **B 断线生命周期**：客机标签关闭后，主机自动回标题、出现「对手已离开」可见提示、
  下行计数停止增长（不再打空气）；重新进入联机面板得到全新会话
- **C 重赛幂等**：结算页注入双击/重复投递/交叉的 rematch，
  两端各只重开一次（`gen` 恰好 +1），比分清零、回到第 1 回合、角色沿用，
  旧对局的迟到快照被 `gen` 隔离丢弃
- **D 客机不自行开局**：客机在收到主机 `start` 前始终停在等待态，`gen` 保持 0
- **E 无页面运行时错误**（含联机页、本地双人、人机全部页面）
- **F 本地双人 / 人机回归**：真实按键脉冲选人、人机计时推进与结算、
  本地「再来一局」路径均不创建任何网络会话，行为与改动前一致

如 Chrome 不在默认路径，设置环境变量 `CHROME_BIN` 指向可执行文件。

## 三、手工双窗口复现（局域网真人操作）

```bash
npm start
```

打开两个浏览器窗口（可一个普通窗口、一个无痕窗口），都访问
`http://localhost:3000/?lan=1`（先开的成为主机）。

| 场景 | 操作 | 预期 |
|:---|:---|:---|
| 正常配对 | 两窗均点「局域网联机对战」，各自选人确认 | 两端同时进入同一对局，角色/回合/比分一致 |
| 客机掉线 | 对战中直接关闭客机窗口 | 主机停手回标题，中央提示「对手已离开」，HUD 消失，不再有快照收发 |
| 主机掉线 | 对战中直接关闭主机窗口 | 客机回标题并提示「对手已离开」，上行输入循环停止 |
| 迟到消息 | 掉线后立刻在旧窗口点按键（若窗口还在） | 服务端回 `room-closed`，客户端不再进入任何对局 |
| 同时重赛 | 两端结算页几乎同时点「再来一局」 | 由主机统一广播一次 rematch，两端各只开一局新比赛，比分 0:0 |
| 重复重赛 | 快速连点「再来一局」 | 同序列号命令被去重，不会一端重开两次、另一端停在结算页 |
| 回菜单 | 任一方点「回到主菜单」/选人页返回 | 房间关闭，另一方收到「对手已离开」回标题；再点联机可建立全新会话 |
| 重连全新会话 | 掉线后任一端再次点「局域网联机对战」 | 新房间、新定时器，旧 `NetSession` 的迟到回调全部失效 |

调试 URL 参数：`&pick=N` 自动确认 N 号角色、`&auto=1` 客机自动驾驶、
`&rt=8` 把单回合压缩到 8 秒（快速验证重赛/结算）。

## 四、本地双人 / 人机回归

- `http://localhost:3000/?select=1` —— 本地双人/人机选人流程不受影响
- `http://localhost:3000/?fight=xiaoniu,jinbao&mode=ai` —— 人机直达对战
- 本地模式下「再来一局」走原有本地路径，不经过任何联机序列号逻辑
