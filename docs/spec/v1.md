# Spec v1: Lofi Lobby

The detailed design behind the [Architecture section of the README](../../README.md#architecture). Decisions in [ADR 001](../adr/001-one-durable-object-per-room.md) to [ADR 004](../adr/004-original-art-in-the-repo-local-assets-ignored.md).

## Flows

**Join.** The page loads the scene and shows "choose your trainer". The click on **enter the room** starts the radio (browsers need a gesture for sound). The client opens `wss://<host>/ws/<room>?client=<per-tab id>` and sends `hello { name, gender }`. The room answers `you { id }`, the current `radio { command }` if any, and `state { players }`; everyone else gets `joined`.

**Walk.** The client moves locally (collision runs on the client) and sends `pos { x, z, dir, step }` at most 15 times a second, only when something changed. Others interpolate toward the last position.

**Chat.** `chat { text }` → the room cleans it and sends `chat { id, name, text, at }` to everyone, sender included. The client adds it to the history and shows a bubble over the speaker for about 4 s (longer for long messages).

**Radio.** See [ADR 002](../adr/002-radio-synced-by-the-clock.md). Admin sends `radio { idx, password }`; on success the room stores and broadcasts `radio { command: { idx, at } }`; on failure it answers `error { msg }` to the sender only.

**Reconnect.** When the socket drops (network hiccup, laptop asleep), the client redraws nobody and retries 2 s later with the same `?client=` id. The server closes the old connection that still carries that id (it announces `left { id }` for it) and accepts the new one, which then receives `you { id }`, the current `radio` and a full `state`. The old id never stays in the room, so a reconnect cannot duplicate its own trainer or keep a ghost.

**Leave.** On close or error the room broadcasts `left { id }`.

## Per-IP state under reconnects

The same person may have up to three tabs; the limits are per IP, not per connection, and they survive a reconnect:

- **Connections.** A connection from an IP already at the limit **replaces the oldest** one on that IP instead of being refused: the old socket is closed with code `4001` and announced as `left`, then the new one is accepted. A reconnect therefore always gets in, even while the server still counts the dropped connection as open.
- **Chat mute.** Strikes and the mute deadline are kept in the object's storage (`mute:<ip>`), so a new connection from a muted IP is still muted; the mute ends by itself at its deadline. Strikes are forgotten (and the stored entry removed) after 30 min quiet.
- **Admin lock.** Wrong passwords are counted in storage (`admin-fail:<ip>`) inside one storage transaction per attempt, so concurrent tries cannot lose a count or slip past a lock. A finished lock starts again from zero failures, and the count restarts at zero when the lock ends.

When a replaced or closed connection was the last one on its IP, its rate buckets are dropped; the persisted mute and lock stay (they belong to the IP).

## Protocol

JSON over WebSocket, documented at the top of [`worker/index.js`](../../worker/index.js). Field names are short and stable; the server validates every one.

| From client | Fields | Server checks |
|---|---|---|
| `hello` | `name`, `gender` | name cleaned to 16 chars; trainer is `male` or `female` |
| `pos` | `x`, `z`, `dir`, `step` | finite, within ±500; `dir` is `down`, `up`, `left` or `right`; `step` 0–3 |
| `chat` | `text` | cleaned to 140 chars; empty is dropped |
| `name` | `name` | as in `hello` |
| `gender` | `gender` | as in `hello` |
| `radio` | `idx`, `password` | constant-time password check; 5 failures per IP lock admin for 15 min (the count is one storage transaction per try) |

## Limits

| Limit | Value |
|---|---|
| Rooms | 1 (`lobby`); other names get 404 |
| Players per room | 100 |
| Message size | 1 KB |
| Rate (bucket size / refill per s) | pos 30 / 20 · chat 8 / 1 · other 10 / 1 |
| Name / chat | 16 / 140 characters |
| Connections per IP | 3; a further connection replaces the oldest on that IP (close code 4001) |
| Chat budget | shared by all connections of one IP; dropped when the last connection on the IP goes away |
| Mute / admin lock | stored per IP; survive reconnects and a restart of the object |
| Spam (rate exceeded, or same text 4+ times in a row within 30 s) | warning → 15 s → 1 min → 5 min → 30 min mute; strikes reset after 30 min quiet |

## Tests

`npm test` starts `wrangler dev` locally with the test config in [`test/`](../../test) and short limits, then drives real WebSocket clients. It covers joining and the snapshot, reconnecting while the old socket still looks open, replacement at the per-IP limit, the shared chat budget, a mute that survives a reconnect and ends by itself, concurrent wrong passwords that all count, a lock that ends and restarts the count, and mute/lock surviving a restart. Client-side reconnect and roster code has unit tests with a fake socket. No YouTube, Cloudflare account or production secret is involved.
