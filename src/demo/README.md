# 性能与命中演示页（Performance & Hit Demo）

一个可直接打开的可观察演示页：画布上铺开大量矩形，并提供**可拖拽**与**可点击选中**两种交互，实时展示帧率、选中数量与命中 id。

## 运行

```bash
npm install
npm run start          # 本地开发服务器 http://localhost:10101
```

构建产物（`npm run start` 会输出到 `dist/`）也可直接用任意静态服务器托管。

### URL 参数

| 参数    | 说明                               | 默认值  |
| ------- | ---------------------------------- | ------- |
| `count` | 矩形数量，必须为正整数，上限 100000 | `20000` |

```text
http://localhost:10101/?count=5000
```

`count` 不是正整数或超过上限时，页面会**回退到默认值 20000**，并在右上角指标面板中给出黄色提示文字，而不是抛错白屏。

## 页面指标

右上角固定面板（`position: fixed` + `z-index: 9999`，缩放窗口时始终可见、不被画布遮挡）实时显示：

1. **FPS（最近 60 帧均值）**：按浏览器帧节拍（`requestAnimationFrame`）统计最近 60 个帧间隔的平均值，拖拽导致主线程繁忙时会真实下降。
2. **选中数量**：当前选中矩形个数。单选模型下为 `0` 或 `1`。
3. **命中矩形 id**：最近一次点击命中的矩形 id；点击空白显示 `none`。

## 交互约定

- **拖拽**：左上角的红色矩形可拖拽，拖拽过程中帧率保持在 30 以上（见下方实测数据）。
- **点击选中**：点击任意矩形只选中它（`选中数量 = 1`，并显示其 id）；点击空白清空选中并把命中 id 置为 `none`。
- **稳定 id**：所有矩形 id 由布局确定性生成（网格为 `rect-0 ... rect-N`，另有 `rect-drag` / `rect-click`），同一位置重复点击结果完全一致。

## 实现结构

| 文件                  | 职责                                                                 |
| --------------------- | -------------------------------------------------------------------- |
| `src/demo/config.ts`  | `count` 参数解析、默认值、上限与回退提示                              |
| `src/demo/layout.ts`  | 确定性布局 `createLayout`、纯几何命中 `hitTest`、拖拽位置同步         |
| `src/demo/selection.ts` | 选中 / 命中指标的状态模型（可订阅）                                 |
| `src/demo/controller.ts` | 点击 → 命中的纯逻辑内核，测试与场景共用同一套代码                  |
| `src/demo/scene.ts`   | Leafer 场景：批量建图、引擎事件转发、拖拽同步、选中高亮、自适应重排    |
| `src/demo/fps.ts`     | 最近 N 帧平均帧率                                                    |
| `src/demo/hud.ts`     | 指标面板 DOM 与更新函数                                              |
| `src/demo/style.ts`   | 页面样式注入与挂载节点                                               |
| `src/demo/main.ts`    | 页面入口：装配上述模块、rAF 采样、resize 自适应                       |

性能相关的关键取舍：

- 2 万个节点一次性 `leafer.add(nodes)` 批量添加，避免逐节点重复排版；
- 矩形均为轴对齐，统一启用 `hitBox` 命中，跳过命中画布像素检测；
- 拖拽帧内只同步数据层坐标，不做 O(n) 查找（拖拽节点在构建时缓存）；
- 窗口缩放走 120ms 防抖，复用已有节点只改坐标与尺寸，不重建场景。

## 自动化测试

```bash
npm test               # 等同 npx vitest run --config vitest.config.ts
```

测试覆盖（`src/test/`）：

- `config.test.ts`：**非法 count 回退**——空串、0、负数、小数、科学计数、字母、混合、超上限、非安全整数，全部回退默认值并带提示文字。
- `hit.test.ts`：**命中判定**——id 唯一稳定、同位置重复点击结果一致、只选中被点矩形、选中切换、点空白清空到 `none`、拖拽后按新位置命中、示例矩形位于最上层。
- `page.test.ts`：集成路径——真实 Leafer 场景 + HUD，校验初始指标、点击矩形 / 空白后的 HUD 文本、非法 count 的页面提示、合法 count 生效、视口变化后的重排与边界、最近 60 帧 FPS 均值。

> 说明：本仓库的快照中 `src/leafer`、`src/ui` 等子模块为空，因此 `vitest.config.ts` 把 `leafer-ui` 解析到已安装的 npm 包（`node_modules/leafer-ui/dist/web.esm.js`），`src/test/setup.ts` 补齐了 jsdom 缺失的 Canvas / PointerEvent 等浏览器全局。

## 实测数据（Chrome 143 headless，1400×900）

在真实 Chrome 中用合成 PointerEvent 驱动真实引擎拖拽，记录 rAF 帧间隔：

| count  | 拖拽平均帧率 | 平均帧间隔 | 渲染耗时（平均） |
| ------ | ------------ | ---------- | ---------------- |
| 20000  | 59.9 FPS     | 16.68 ms   | 2.0 ms           |
| 50000  | 59.9 FPS     | 16.68 ms   | 5.7 ms           |
| 100000 | 59.2 FPS     | 16.90 ms   | 9.4 ms           |

拖拽帧率稳定在 30 以上（实际接近 60）。headless 环境无 GPU 合成，真实设备通常更好。
